# claude-opus-4-7
Claude Opus 4.7, Anthropic's Opus-tier (frontier) model released 2026-04-16, now legacy on the API (retirement not before 2027-04-16) and scheduled for retirement from GitHub Copilot on 2026-10-02; API ID `claude-opus-4-7`, Bedrock `anthropic.claude-opus-4-7`. Source: [Claude Opus 4.7 overview](https://platform.claude.com/docs/en/models/opus-4-7/overview).
- Context window 1M tokens; max output 128K synchronous, 300K on Batches with beta `output-300k-2026-03-24`. Source: [Claude Opus 4.7 overview](https://platform.claude.com/docs/en/models/opus-4-7/overview).
- Thinking: adaptive only; thinking is off when the `thinking` parameter is omitted; `budget_tokens` returns 400 on Claude 4.7 and later. Source: [Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices).
- Non-default `temperature`/`top_p`/`top_k` return 400, a constraint "previously introduced on Claude Opus 4.7". Source: [What's new in Claude Sonnet 5](https://platform.claude.com/docs/en/models/sonnet-5/whats-new-sonnet-5).
- Effort levels `low`, `medium`, `high`, `xhigh`, `max`; API default `high`; Anthropic: "Start with `xhigh` for coding and agentic use cases", `max` "can lead to overthinking"; respects effort more strictly than Opus 4.6 at `low`/`medium`; no per-message effort. Source: [Effort](https://platform.claude.com/docs/en/build-with-claude/effort).
- Fast mode not available (`speed: "fast"` returns an error). Source: [Pricing](https://platform.claude.com/docs/en/about-claude/pricing).
- New tokenizer (first used on this model): the same input maps to roughly 1.0-1.35x more tokens than before. Source: [Introducing Claude Opus 4.7](https://www.anthropic.com/news/claude-opus-4-7).
- Reliable knowledge cutoff Jan 2026. Source: [Claude Opus 4.7 overview](https://platform.claude.com/docs/en/models/opus-4-7/overview).
- Price per MTok: input $5, output $25, 5-minute cache write $6.25, 1-hour cache write $10, cache read $0.50; batch $2.50/$12.50; 1M window at standard rate; `inference_geo: "us"` 1.1x. Source: [Pricing](https://platform.claude.com/docs/en/about-claude/pricing).

Inference for review stages (not measured here):
- Finder diff size: no benchmark ties recall to diff lines. Inference: about 800-1,000 changed lines with context per finder, keeping input well under 128k: strong at resolving code (SWE-bench Pro 64.3%) but its multi-needle retrieval is the weakest of the four here (MRCR 8-needle 59.2% at 256K, 32.2% at 1M; Context Arena AUC@128k about 31% at every effort). In Copilot the default variant reported at 200K / 32K output and `medium` only, so `xhigh` needs the 1M variant.
- Judge batch: Inference: 3-4 candidates per context, each check rerun with its raw output quoted back, since pilot users saw it blame its own test failures on pre-existing breakage and over-trust first diagnoses. Terminal-Bench 2.0 69.4% was measured with thinking off, so rerunning checks does not require high effort.
- Effort: finder `xhigh` (Anthropic's starting point for coding; literal instruction following, so use a coverage-first prompt), with `max_tokens` of 64k or more. Judge rerunning a check: `high`. Writer: `medium`. Triage: `low`. In Copilot it retires 2026-10-02, so a pipeline using it there needs a replacement within about a week.
