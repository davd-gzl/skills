# kimi-k3
Moonshot AI's flagship open-weight multimodal MoE (2.8T total, 104B active, Kimi K3 License), API id `kimi-k3`, in OpenCode as `opencode/kimi-k3` (Zen) and `opencode-go/kimi-k3`; announced 2026-07-16, weights promised by 2026-07-27, frontier tier.
- Release: announced 2026-07-16 (Fortune, Artificial Analysis, models.dev); the tech blog says "full model weights will be released by July 27, 2026". Source: [Fortune, 2026-07-16](https://fortune.com/2026/07/16/moonshots-kimi-k3-pushes-chinese-ai-into-fable-level-territory/), [Kimi K3 tech blog](https://www.kimi.ai/blog/kimi-k3).
- Architecture: 2.8T total / 104B activated, 896 experts with 16 selected, 69 KDA + 24 Gated MLA layers, context length 1,048,576, MXFP4 weights (quantization-aware training), text and image input. Source: [MoonshotAI/Kimi-K3 README](https://github.com/MoonshotAI/Kimi-K3).
- Context 1,048,576 tokens; `max_completion_tokens` defaults to 131,072 and can go to 1,048,576. Source: [Kimi K3 quickstart, Kimi API docs](https://platform.kimi.ai/docs/guide/kimi-k3-quickstart).
- Thinking is always on; `reasoning_effort` accepts `low`, `high`, `max` (default `max`); temperature 1.0, top_p 0.95, n 1 and penalties 0 are fixed. Source: [Kimi K3 quickstart, Kimi API docs](https://platform.kimi.ai/docs/guide/kimi-k3-quickstart), [Thinking effort, Kimi API docs](https://platform.kimi.ai/docs/guide/use-thinking-effort).
- Multi-turn and tool loops must return the complete assistant message, `reasoning_content` and `tool_calls` included, unchanged; the blog warns quality "may become highly unstable" if a harness drops historical thinking or switches a running session to K3. Source: [Kimi K3 quickstart](https://platform.kimi.ai/docs/guide/kimi-k3-quickstart), [Kimi K3 tech blog](https://www.kimi.ai/blog/kimi-k3).
- OpenCode Zen and Go `kimi-k3`: context 1,048,576, output 131,072, reasoning option effort with only `max`; text, image and video in. Source: [models.dev api.json, providers opencode and opencode-go](https://models.dev/api.json).
- Request to expose `low` and `high` in opencode-go (2026-07-23) closed as not planned, so OpenCode's hosted endpoints run K3 at max only. Source: [opencode issue #38429](https://github.com/anomalyco/opencode/issues/38429).
- Direct Moonshot provider in models.dev lists toggle plus effort `low`, `high`, `max`. Source: [models.dev api.json, provider moonshotai](https://models.dev/api.json).
- Price, Moonshot API, per 1M tokens: input (cache miss) $3.00, cached input (hit) $0.30, cache write $3.00 (5 min TTL) or $6.00 (1 h TTL), output $15.00; no long-context tier listed. Source: [Pricing, Kimi API docs](https://platform.kimi.ai/docs/pricing/chat).
- Price, OpenCode Zen: input $3.00, output $15.00, cached read $0.30, cached write not listed, no context tier. Source: [OpenCode Zen docs](https://opencode.ai/docs/zen).
- OpenCode Go ($10/month plan): same rates, about 110 requests per 5 h, 250 per week, 490 per month. Source: [OpenCode Go docs](https://opencode.ai/docs/go).

- Weakness, user reports collected by Zvi Mowshowitz, 2026-07-20: token hungry (Dean Ball), slowest versus Opus, Sonnet and Grok 4.5 in one frontend eval (Tushit), capacity constrained (Jake Halloran), reaches "70-90%" of the asked result (Daniel Mulec), weaker than Grok 4.5 on security benchmarks (s1r1us). Source: [On Kimi K3, Don't Worry About the Vase](https://thezvi.substack.com/p/on-kimi-k3-its-capabilities-and-related).

Source: [opencode issue #50232](https://github.com/anomalyco/opencode/issues/50232), [opencode PR #50383](https://github.com/anomalyco/opencode/pull/50383), [opencode issue #38378](https://github.com/anomalyco/opencode/issues/38378).

Inference for review stages (not measured here):
- Finder diff size: about 400 to 600 changed lines per finder; Semgrep measured F1 falling to about 6% on the largest enterprise-style repo and precision below peers, so smaller slices of the diff are safer despite the 1M window. Basis: [Semgrep](https://semgrep.dev/blog/2026/kimi-k3s-code-security-results-lack-precision/).
- Judge batch: 5 to 6 candidates per context; as a verifier it converges fast (median 12 turns) with 92.3% pooled precision, and BrowseComp held up to 300K with compaction. Basis: [Aikido](https://www.aikido.dev/blog/ai-model-benchmarks-aug-21-2026), [MoonshotAI/Kimi-K3 README](https://github.com/MoonshotAI/Kimi-K3).
- Effort: through OpenCode Zen or Go only `max` exists, so every stage runs max. On the direct Moonshot API: finder `max`, judge rerunning a check `high` (96.4% vs 96.6% at max on agentic SWE tasks, at a fraction of max's cost), writer `high`, triage `low`. Basis: [arXiv 2608.25399](https://arxiv.org/html/2608.25399), [opencode issue #38429](https://github.com/anomalyco/opencode/issues/38429).
